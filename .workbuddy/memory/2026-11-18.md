## giscus 评论「在 GitHub 上发言 · 可传图」入口（A 方案）

- 背景：giscus 输入框不支持上传附件（官方限制：OAuth 只拿到代发评论权限，GitHub 网页的上传走未文档化的 `uploads.github.com/user-attachments/assets` 端点）；博客端未登录时输入框还会被禁用。评论/图片都存在 GitHub Discussions + 附件 CDN，不进仓库、不进本地管理台。
- 实现：评论区标题右侧加按钮（仅 giscus provider）。兜底 href = `https://github.com/{repo}/discussions?discussions_q={slug}`；开启 `commentConfig.giscus.emitMetadata`，主页面监听 giscus iframe 的 message，用 `IDiscussionData.url` 把 href 换成精确 Discussion URL。按 `event.source === iframe.contentWindow` 定位所属评论区，避免 Swup 切页串到旧 Discussion；只接受 https + github.com，并校验 event.origin 等于 client.js 的 origin。
- 改动文件：`CommentSection.astro`（按钮 + `discussionsSearchUrl`）、`Giscus.astro`（`handleDiscussionMetadata`）、`commentConfig.ts`（`emitMetadata: true`）、i18n 新增 `commentsOpenOnGithub`（`i18nKey.ts` + 10 个语言文件）。
- 验证：`astro check` 0 errors、Biome 14 文件通过、`astro build` 46 页、产物 12 个页面含按钮、浏览器实测「兜底链接 → metadata 替换为 discussions/4 → 点击 popup 新窗口」全通过。
- 两个坑：`i18nKey-runtime.mjs` 是 Proxy，新增 key 无需同步；`Giscus.astro` 的 `<script>` 被**内联**进页面 HTML，不在 `dist/_astro/*.js`，查打包产物时别只搜 _astro 目录。
- `astro build` 会删掉被 git 跟踪的 `src/generated/local-icon-collections.ts.tmp`（图标生成的中间产物），提交前记得 `git restore` 该文件，避免混入无关删除。
