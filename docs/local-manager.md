# 本地管理台

这是供博主在自己电脑上运行的写作与定制工具，不是网站注册系统。后台直接读取、修改仓库原来的 Markdown、配置和数据；网站继续使用同一套 Shirone 页面。管理台、API 和备份不会进入 GitHub Pages，访客没有编辑入口。

## 启动

在项目目录运行：

```powershell
pnpm.cmd manage
```

打开 `http://127.0.0.1:4319/`。也可以双击项目中的 `管理博客.cmd`。关闭这个终端就会关闭管理服务。端口已占用时，可以设置 `LOCAL_MANAGER_PORT` 后再次启动。

第一次使用先安装依赖：`pnpm.cmd install --frozen-lockfile`。需要 Node.js 22.12 或更高版本及 pnpm。

在另一个终端启动网站预览：

```powershell
pnpm.cmd dev --host 127.0.0.1 --port 4321
```

博客预览地址是 `http://127.0.0.1:4321/blog/`。管理台的正文预览支持基本 Markdown；Shirone 自定义语法、完整排版和配置变更以这个网站预览为准。某些配置修改需要重启预览服务。

## 可以维护什么

| 入口 | 对应文件 | 编辑方式 |
| --- | --- | --- |
| 文章与页面 | `src/content/` 下的 Markdown / MDX | 元数据表单、正文编辑、源码模式 |
| 站点设置 | `src/config/` | 常见静态字段的可视化表单，以及完整源码模式 |
| 个人资料 | `src/config/profileConfig.ts` | 名字、简介、头像等表单字段 |
| 横幅与打字动效 | `src/config/siteConfig.ts` | 标题、副标题、图片、速度、循环等设置 |
| 导航与侧栏 | `navBarConfig.ts`、`sidebarConfig.ts` | 配置源码；引用与复杂结构保留原写法 |
| 书单、番剧、友链、项目等 | `src/data/` | 编辑原始 TypeScript / JSON 数据 |
| 相册说明 | `public/` 下的 JSON / Markdown | 编辑原文件 |
| 图片 | `public/`、`src/assets/images/` | 浏览、上传、复制引用路径 |
| 中文及其他界面文案 | `src/i18n/languages/` | 编辑语言文件源码 |
| 站点样式 | `src/styles/personal-blog.css` | 编辑自定义样式源码 |

新建内容时选择文章、随记、思考、札记、系列或页面，使用稳定的英文文件名。新文章、随记、札记默认是草稿；思考、系列和自定义页面原有数据模型不支持草稿隐藏，它们会在发布构建时生成页面。新增自定义页面文件不会自动增加主题中不存在的路由，现有“关于”等页面可以直接编辑。

图片上传至 `public/images/uploads/`，用唯一文件名避免覆盖原图。复制 `/images/uploads/...` 引用后，可填入头像、封面、横幅配置或 Markdown 图片语法。允许 JPEG、PNG、WebP、GIF、AVIF，单张最多 10 MiB，不接受 SVG / HTML。已有导入至 `src/assets/images` 的图片也可浏览；其引用格式与 `siteConfig.ts` 的 `assets/images/...` 一致。

设置表单只处理文件中直接写出的字符串、数字、布尔值和字符串数组。导入引用、函数、导航预设和复杂数组请使用源码模式，后台不会执行配置来读取它。源码保存会检查基本语法；完整的类型、内容和站点兼容性在“检查与构建”中验证。

## 保存、恢复、发布

1. 编辑后点击保存，或按 `Ctrl+S` / `⌘S`。保存只更新本地文件，不会自动上线。
2. 打开网站预览检查。若文件同时被 VS Code 等其他程序改动，后台会提示版本冲突，避免直接覆盖。
3. 每次覆盖、删除和恢复前都会在 `.local-manager/backups/` 保存原始版本。在历史中可以恢复，也可以恢复到恢复前的版本。该目录已加入 `.gitignore`，不会被网站构建或提交发布。
4. 准备公开的文章、随记或札记，先取消“草稿”并保存。编辑器提示“草稿，发布后仍不公开”时，即使提交部署也不会在网站展示。源码模式可将 `draft` 改为 `false` 后保存。
5. 点击顶栏保存旁的“发布”（手机上也可见），或左侧“检查与发布”，打开发布面板。这个入口只切换面板，不会直接推送；未保存时仍会提示确认是否放弃修改。
6. 在发布面板查看变更清单，点击“运行检查”运行 `astro check` 和正式构建。填写更新说明，再点击“提交并发布”并确认。后台再次检查构建，把通过本后台保存的变更提交到 `main` 并推送 `origin main`。GitHub Actions 的 **Deploy blog to GitHub Pages** 成功后，线上内容才更新。

后台不会把其他未经它保存的文件加入提交。若已有暂存修改、落后远端、存在未推送提交或当前不在 `main`，会停止并提示在终端处理。发布不会自动合并、强制推送或重置仓库。推送失败时会保留本地提交，按日志在终端重试 `git push origin main`。

为保证本地检查与线上提交使用一致的构建输入，发布开始和检查完成后都会检查其他修改。若 `src/`、`public/`、`scripts/`、依赖补丁、构建配置、包与锁文件或 GitHub 工作流存在未纳入此次发布的修改，会停止发布：可编辑文件请先在管理台打开并保存，其他修改请在终端处理。普通笔记、文档及 `artifacts/` 下的验证产物不会因此被加入提交。

**公开仓库里的 Markdown 源文件和图片也会公开。** `draft: true` 控制正式网站是否展示，不代表仓库文件保密；请勿将密码或私密资料写进这些文件。

## 范围与边界

- 管理服务只监听 `127.0.0.1`，需要每次启动生成的会话令牌，拒绝外部来源和不匹配的 Host。它没有注册、账号或远程管理能力，不要通过代理、隧道或公网转发开放这个端口。
- 管理台只能操作明确开放的内容、配置、数据和图片路径，不能读取 `.env`、`.git`、SSH 密钥或任意磁盘文件；也不会把 GitHub 凭据发到浏览器。
- 开放的是博客内容与配置，不是任意程序源码。重命名路由、增加全新页面类型、修改主题组件结构仍属于开发工作。
- 当前工具维护的是本仓库的本地内容。如果以后启用 `CONTENT_DIR` / 外部内容仓覆盖，应先调整管理台的内容根目录，避免改错来源。

## 验证

```powershell
node --test tests/manage/store.test.mjs tests/manage/documents.test.mjs tests/manage/server.test.mjs tests/manage/jobs.test.mjs
```

文件存储测试使用临时目录，发布测试只向临时的本机 bare Git 仓库推送，不会修改真实文章或推送到 GitHub。
